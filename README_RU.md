# OpenSig — подпись и проверка файлов для Windows

Простой графический инструмент для создания и проверки **двоичных** файловых подписей `.sig`, совместимых с командой `openssl dgst -sha256`. Интерфейс полностью на русском.

## Что умеет

- Перетаскивать **один или несколько** любых файлов из Проводника прямо в окно (или выбирать их кнопкой). Также можно перетащить файл на значок `OpenSig.exe`/ярлык: откроется приложение и сразу подпишет файл.
- Создавать рядом с исходным файлом `имя_файла.ext.sig`.
- Проверять подписи: можно перетащить `имя_файла.ext` **или** `имя_файла.ext.sig`. Подпись и исходный файл должны лежать рядом.
- Создавать пары ключей RSA-3072 и сохранять их в формате PEM.
- Подключать имеющиеся RSA-ключи PEM из OpenSSL; поддерживаются незашифрованные ключи и зашифрованные PKCS#8 (`BEGIN ENCRYPTED PRIVATE KEY`).
- Обрабатывать большие файлы потоково (не загружая исходные файлы целиком в ОЗУ).
- Подписывать и проверять файлы **без установки OpenSSL** на компьютере пользователя. Используется встроенная криптография .NET.

## Запуск

На Windows 10/11 (x64) выполните:

1. Установите **.NET 10 SDK**: https://dotnet.microsoft.com/download/dotnet/10.0 (только для сборки).
2. Дважды щёлкните `build-win-x64.cmd`.
3. Запустите `dist\OpenSig.exe`.

Сборка получается **самодостаточной**: конечным пользователям не нужно устанавливать .NET или OpenSSL. Для переноса достаточно `OpenSig.exe`.

> В этом архиве исходный код и скрипт сборки. Готового `.exe` нет: для сборки Windows-приложения используется Windows с .NET SDK.

## Использование

**Создание подписи.** При первом запуске OpenSig автоматически создаёт ключи в `%LOCALAPPDATA%\OpenSig\keys`. Включите режим **«Создать подпись»**, затем перетащите файл на окно. В той же папке появится `файл.ext.sig`.

**Проверка подписи.** Включите **«Проверить подпись»**. Выберите открытый ключ (при необходимости) и перетащите `файл.ext` или `файл.ext.sig`. Программа найдёт второй файл рядом и покажет результат.

**Своя пара ключей.** Нажмите **«Создать ключи»** и выберите папку. Существующие ключи не будут перезаписаны. Если вы создаёте новую пару, для проверки старых подписей потребуется соответствующий **старый** публичный ключ.

**Существующие ключи.** Кнопки **«Выбрать…»** позволяют указать приватный или публичный RSA-ключ PEM из OpenSSL. Используются RSA, SHA-256 и стандартное дополнение PKCS#1 v1.5.

## Команды OpenSSL

Создать подпись, совместимую с OpenSig:

```powershell
openssl dgst -sha256 -sign private.pem -out "example.zip.sig" "example.zip"
```

Проверить подпись OpenSig через OpenSSL:

```powershell
openssl dgst -sha256 -verify public.pem -signature "example.zip.sig" "example.zip"
```

Вывести открытый ключ из закрытого ключа:

```powershell
openssl pkey -in private.pem -pubout -out public.pem
```

Файл `.sig` — это **сырые бинарные байты RSA-подписи**, а не текст и не сертификат.

## Важные замечания по безопасности

- **Никому не отправляйте закрытый ключ `private.pem`.** Встроенный генератор создаёт его **без пароля** ради простоты. Храните его в защищённом месте и делайте резервную копию. Для дополнительной защиты можно создать зашифрованный RSA PKCS#8 ключ с помощью OpenSSL и выбрать его в приложении.
- Публичный ключ можно передавать вместе с файлами, но получатель должен **достоверно знать**, что ключ принадлежит вам. Подпись без доверия к ключу не доказывает личность отправителя.
- Содержимое файла подпись **не шифрует**; оно остаётся читаемым.
- Повторная подпись одного файла спросит разрешение заменить существующий `.sig`.
- Поддерживаются RSA-подписи, созданные `openssl dgst -sha256` в стандартном режиме PKCS#1 v1.5; RSA-PSS, ECDSA, Ed25519, CMS/PKCS#7 здесь не поддерживаются.
- При проверке отдельной `.sig` программа предполагает, что исходный файл находится рядом и называется так же **без финального `.sig`**.

## Структура проекта

- `OpenSig.csproj` — проект WinForms на .NET 10.
- `Program.cs` — весь интерфейс, генерация PEM-ключей, подпись, проверка, drag-and-drop.
