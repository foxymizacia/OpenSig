# OpenSig 1.1 — подписи OpenSSL для Windows

Простое Windows-приложение на C# / WinForms: можно перетащить один или несколько файлов на окно и получить бинарные `.sig` рядом с файлами. Есть проверка подписей, генерация ключей, два алгоритма на выбор: **RSA-3072 / SHA-256** и **Ed25519**.

## Возможности

- Drag & Drop файла/нескольких файлов прямо на окно; файлы также можно перетаскивать на `OpenSig.exe` или ярлык.
- Выходной файл называется, например, `example.zip.sig`. Он содержит **только сырые байты подписи**, без собственного заголовка.
- Проверка перетаскиванием как исходного файла, так и его `.sig` (оба должны лежать рядом).
- Переключение алгоритма через раскрывающийся список **«Алгоритм»**.
- Генерация и загрузка PEM-ключей (`PRIVATE KEY`, `ENCRYPTED PRIVATE KEY`, `PUBLIC KEY`) для соответствующего алгоритма.
- **Разные настройки и разные пары ключей для RSA и Ed25519**. RSA-ключи предыдущей версии сохраняются и продолжают работать.
- Новая пара никогда не перезаписывает старые файлы ключей.
- Не требуется установленный OpenSSL ни для создания, ни для проверки `.sig`.

## Сборка и запуск

1. На Windows 10/11 x64 установите [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0).
2. Распакуйте ZIP и запустите `build-win-x64.cmd`.
3. Запустите `dist\OpenSig.exe`.

Сборка загружает из NuGet библиотеку **BouncyCastle.Cryptography 2.7.0** (для Ed25519), поэтому **для первой сборки потребуется интернет**. Приложение собирается как *single-file self-contained EXE*. На компьютере, где его запускают, **не требуется** устанавливать OpenSSL, .NET или NuGet.

> В архиве — исходный проект. Windows EXE в нём не поставляется. На этой стороне Windows-сборку и тест GUI запустить было невозможно.

## Использование

1. Выберите **RSA-3072 / SHA-256** или **Ed25519** справа от переключателя режимов.
2. При первом выборе алгоритма приложение создаёт свою пару ключей в `%LOCALAPPDATA%\OpenSig\keys`. Если вы устанавливали старую версию, RSA-ключи будут подхвачены автоматически.
3. Выберите режим **«Создать подпись»**, перетащите файл в окно. Рядом появится `имя_файла.sig`.
4. Для проверки переключите режим на **«Проверить подпись»** и перетащите файл или `.sig`. Для проверки требуется соответствующий **публичный** ключ и выбранный **тот же алгоритм**.
5. Для использования своих ключей нажмите **«Выбрать…»** напротив нужного ключа. Кнопка **«Создать ключи»** создаёт дополнительную пару в выбранной папке.

### Файлы ключей по умолчанию

| Алгоритм | Закрытый PEM | Открытый PEM |
| --- | --- | --- |
| RSA-3072 | `private.pem` | `public.pem` |
| Ed25519 | `private_ed25519.pem` | `public_ed25519.pem` |

## Проверка совместимости с OpenSSL

### Ed25519

Ed25519 использует **чистый Ed25519 по RFC 8032**, без предварительного SHA-256 и без Ed25519ph. Файл `.sig` имеет размер **64 байта**. Установленный OpenSSL 3.x может использовать эти файлы напрямую:

```powershell
# Генерация PEM-ключей средствами OpenSSL (при желании):
openssl genpkey -algorithm ED25519 -out private_ed25519.pem
openssl pkey -in private_ed25519.pem -pubout -out public_ed25519.pem

# Создать подпись OpenSSL и затем проверить её в OpenSig:
openssl pkeyutl -sign -rawin -inkey private_ed25519.pem -in "example.zip" -out "example.zip.sig"

# Проверить подпись OpenSig с помощью OpenSSL:
openssl pkeyutl -verify -rawin -pubin -inkey public_ed25519.pem -in "example.zip" -sigfile "example.zip.sig"
```

**Важно:** `openssl dgst -sha256 -sign` **не подходит** для Ed25519. Здесь нужно использовать `openssl pkeyutl -rawin`.

### RSA / SHA-256 (как в старой версии)

```powershell
openssl dgst -sha256 -sign private.pem -out "example.zip.sig" "example.zip"
openssl dgst -sha256 -verify public.pem -signature "example.zip.sig" "example.zip"
```

RSA использует PKCS#1 v1.5 (не RSA-PSS). Для больших файлов RSA/SHA-256 обрабатывает данные потоково.

## Важное ограничение Ed25519

**При выборе Ed25519 максимальный размер одного файла — 256 МиБ**. Это ограничение конкретной реализации: чистый Ed25519 требует обработки сообщения целиком, а используемая реализация Bouncy Castle буферизует его в оперативной памяти. Для файлов большего размера выберите RSA/SHA-256 — у него такого ограничения нет. Подменять Ed25519 подписью предварительно вычисленного SHA-256 нельзя: она уже не проверялась бы как подпись исходного файла командой `openssl pkeyutl -rawin`.

## Замечания по безопасности

- **Не передавайте никому закрытые PEM-ключи.** Сгенерированные в приложении закрытые ключи не шифруются паролем; защищайте их доступом к файлам и резервной копией.
- Можно выбрать зашифрованный PKCS#8 PEM (если алгоритм шифрования поддерживает Bouncy Castle/.NET) — программа попросит пароль перед подписанием.
- Публичный ключ можно распространять, но получатель должен предварительно убедиться, что он действительно ваш.
- `.sig` не шифрует содержимое файла; подпись служит проверке целостности и подлинности относительно доверенного ключа.
- Файл `.sig` **не содержит сведений об алгоритме или ключе**: перед проверкой нужно выбрать Ed25519 или RSA и подходящий открытый ключ.
- При существовании одноимённого `.sig` приложение спросит, можно ли его заменить.

## Состав проекта

- `OpenSig.csproj` — проект Windows Forms, зависимость на Bouncy Castle.
- `Program.cs` — интерфейс, выбор алгоритма, RSA, Drag & Drop, сохранение настроек.
- `Ed25519Crypto.cs` — генерация ключей Ed25519, PKCS#8/SPKI PEM, создание и проверка подписей.
- `build-win-x64.cmd` — сборка самостоятельного Windows EXE.
